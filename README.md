# Crypto Price: ตรวจจับการปั่นราคาคริปโตในตลาดไทยด้วย Big Data (Bitkub)

โปรเจกต์ Big Data ที่ดึงแท่งเทียนรายนาทีของเหรียญยอดนิยมบน **Bitkub** ย้อนหลัง 1 ปี (หลักสิบล้านแถว)
เก็บเป็น Data Lake แบบ Medallion แล้วใช้ทำ 2 เรื่อง:
- **ตรวจจับรูปแบบ pump & dump:** ราคาพุ่งแรงพร้อม volume ผิดปกติ แล้วร่วงกลับ
- **พยากรณ์ volume และความผันผวน** รวมถึง early warning ว่าสัญญาณแรกจะกลายเป็น pump หรือไม่

> ⚠️ เป็นงานวิเคราะห์ข้อมูลเพื่อการศึกษา ระบบบอกได้แค่ "รูปแบบที่น่าสงสัย" ไม่ได้ยืนยันว่ามีผู้ปั่นราคา และไม่ใช่คำแนะนำการลงทุน

```
 Bitkub Public API (ฟรี ไม่ต้องใช้ key)
       │  bk_01  bitkub_ingestion_dag   ทุกชั่วโมง :05 (ครั้งแรก = backfill 365 วัน)
       ▼
 ┌──────────────────── SeaweedFS (S3) : bucket bitkub-lake ────────────────────┐
 │ bronze/candles/symbol=XXX_THB/*.parquet   แท่งเทียน 1 นาทีดิบ (OHLCV)          │
 │ bronze/ticker/dt=YYYY-MM-DD/*.parquet     ภาพรวมตลาด 24 ชม. ทุกชั่วโมง           │
 │        │  bk_02  bitkub_lakehouse_dag   ทุกชั่วโมง :25 (DuckDB)                  │
 │        ▼                                                                    │
 │ silver/features/symbol=XXX_THB/data.parquet  dedupe + feature รายนาที         │
 │        ▼                                                                    │
 │ gold/{events, event_candles, symbol_hourly, market_hourly, coin_stats}      │
 └────────┬─────────────────────────────────────────────────────────────────────┘
          │ COPY เข้า Postgres (postgres_target)
          ▼
 bk_03  bitkub_ml_pipeline_dag  ทุก 6 ชม. ── 5 โมเดล + champion-challenger
        bitkub_forecast_publish_dag  หลัง gold อัปเดตทุกชั่วโมง ── ออกค่าพยากรณ์ 6 ชม. ใหม่ (ไม่เทรน)
          ▼
 FastAPI  →  http://localhost:8002  (Dashboard)
```

## วิธีรัน

ต้องมี [Docker Desktop](https://www.docker.com/products/docker-desktop/) ก่อน (แนะนำให้ Docker ใช้ RAM อย่างน้อย 4 GB)

```bash
git clone https://github.com/nattapat3743/crypto-price-thailand.git
cd crypto-price-thailand
cp .env.example .env        # Windows (PowerShell): copy .env.example .env
docker compose up -d --build
```

ครั้งแรกใช้เวลาหลายนาที เพราะ Airflow ต้องติดตั้ง `duckdb`, `pyarrow` และ `scikit-learn` เพิ่ม

1. เปิด Airflow ที่ http://localhost:8081 (user/pass: `airflow` / `airflow`)
2. **Unpause `bitkub_ingestion_dag`**
   - รันครั้งแรกจะ backfill ย้อนหลัง 365 วัน ใช้เวลาประมาณ 10–15 นาที
   - รอบต่อไปดึงแค่ชั่วโมงล่าสุด ใช้เวลาประมาณ 1 นาที
3. **Unpause `bitkub_lakehouse_dag`** แล้วกด ▶ Trigger หลัง backfill เสร็จ (ต่อจากนั้นรันเองทุกชั่วโมง)
4. **Unpause `bitkub_ml_pipeline_dag`** แล้วกด ▶ Trigger เพื่อเทรนโมเดล (ต่อจากนั้นรันเองทุก 6 ชั่วโมง)
   - `bitkub_forecast_publish_dag` เปิดไว้ให้แล้ว รันเองทุกครั้งที่ `bitkub_lakehouse_dag` เสร็จ เพื่อออกค่าพยากรณ์ใหม่ทุกชั่วโมง
5. เปิด Dashboard ที่ http://localhost:8002

| URL | ใช้ทำอะไร |
|---|---|
| http://localhost:8002 | **Dashboard** |
| http://localhost:8081 | Airflow |
| http://localhost:9021/buckets/bitkub-lake/ | ดูไฟล์ Parquet ใน Data Lake ผ่านเว็บ |
| `localhost:9020` | S3 API (DuckDB, boto3 หรือ aws cli ต่อจากเครื่องได้) |
| `localhost:5435` | Postgres ปลายทาง (etluser / etlpass / etl_db) |

port ไม่ชนกับโปรเจกต์ `airflow-docker-flight-traffic` แต่ถ้าเครื่องให้ Docker ใช้ RAM แค่ 4 GB ควรเปิดทีละโปรเจกต์

### ตั้งค่า (`.env`)
| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `BITKUB_TOP_N` | 50 | เก็บกี่เหรียญ (คู่ THB ที่ volume สูงสุด ไม่นับ stablecoin) |
| `BITKUB_BACKFILL_DAYS` | 365 | ดึงย้อนหลังกี่วันตอนรันครั้งแรก |
| `DUCKDB_MEMORY_LIMIT` | 1GB | RAM สูงสุดของ DuckDB ต่อ task ถ้าเกิน DuckDB จะ spill ลงดิสก์เอง |

## ไฟล์ในโปรเจกต์

| ไฟล์ | หน้าที่ |
|---|---|
| `dags/bitkub_lake.py` | โค้ดกลาง: เรียก Bitkub API (retry + เว้นจังหวะ), เชื่อม DuckDB กับ S3, เกณฑ์การตรวจจับ |
| `dags/bk_01_ingestion.py` | เลือก top N เหรียญ → ดึงแท่งเทียนต่อจากจุดล่าสุด (จำไว้ใน `ingest_state`) → bronze |
| `dags/bk_02_lakehouse.py` | bronze → silver (feature) → gold (เหตุการณ์ + สรุปรายชั่วโมง) → Postgres |
| `dags/bk_03_ml_pipeline.py` | 5 โมเดล เทรนทีละตัว, champion-challenger + DAG `bitkub_forecast_publish_dag` ที่ออกค่าพยากรณ์ใหม่ทุกชั่วโมง |
| `model_service/api.py` | API `/api/*` สำหรับ Dashboard |
| `model_service/dashboard.html` | หน้า Dashboard |
| `docker-compose.yaml` | ทั้งระบบ: Airflow, Postgres ×2, Redis, SeaweedFS, FastAPI |

## ข้อมูลและขนาด

- แหล่งข้อมูลคือ endpoint `tradingview/history` ของ Bitkub ให้แท่งเทียน 1 นาที (เวลา, เปิด, สูง, ต่ำ, ปิด, volume)
- **มีแท่งเฉพาะนาทีที่มีการซื้อขาย:** เหรียญใหญ่มีเกือบทุกนาที เหรียญเล็กมีแค่บางนาที สัดส่วนนี้คือ "สภาพคล่อง"
- 50 เหรียญ × 365 วัน ≈ **10–16 ล้านแถว** (ขึ้นกับอายุเหรียญ)

## รายละเอียดแต่ละชั้น

**Bronze** เก็บแท่งเทียนดิบไม่แก้ไข
- 1 ไฟล์ต่อเหรียญต่อการดึง 1 ครั้ง
- ดึงซ้อนแท่งสุดท้ายไว้ 1 แท่งเสมอ เพราะแท่งของนาทีปัจจุบันอาจยังไม่ปิด

**Silver** คือ feature รายนาที ประมวลผลทีละเหรียญเพื่อคุม RAM:
- dedupe: ts ซ้ำจะเก็บแถวที่ดึงมาล่าสุด
- `chg_5m`: % เปลี่ยนจากราคาเปิดเมื่อ 5 นาทีก่อน
- `vol_x_5m`: volume 5 นาทีเทียบค่าปกติ (เฉลี่ยต่อนาทีใน 7 วันก่อนหน้า นาทีที่ไม่มีการซื้อขายนับเป็น 0)
- `active_share_1d`: สัดส่วนนาทีที่มีการซื้อขายใน 24 ชม. หรือสภาพคล่อง
- `max_high_next60` / `min_low_next60` / `close_next15`: ใช้ติดป้ายคำตอบให้โมเดลเท่านั้น ไม่ได้ใช้เป็น feature

**Gold**
- `gold_events` เก็บเหตุการณ์ต้องสงสัยที่ราคา +5% ใน 5 นาทีและ volume ≥ 5 เท่า ถ้าสัญญาณห่างกันไม่เกิน 30 นาทีนับเป็นเหตุการณ์เดียว แต่ละเหตุการณ์มีข้อมูล:
  - จุดสูงสุด และ % ที่ร่วงใน 60 นาที
  - เวลาที่ใช้เสียกำไรคืนครึ่งหนึ่ง
  - `is_pump_dump`: เสียกำไรคืนครึ่งหนึ่งภายใน 60 นาทีหรือไม่
  - `concurrent_symbols`: จำนวนเหรียญอื่นที่พุ่งพร้อมกันใน ±10 นาที ถ้าตั้งแต่ 2 ขึ้นไป น่าจะเป็นข่าวหรือทั้งตลาดขยับ ไม่ใช่การปั่นเหรียญเดียว
- `gold_event_candles` เก็บแท่งเทียนรอบเหตุการณ์ ใช้วาดกราฟ
- `gold_symbol_hourly` / `gold_market_hourly` เก็บ volume และความผันผวนรายชั่วโมง ใช้พยากรณ์
- `gold_coin_stats` เก็บสภาพคล่อง, volume เฉลี่ย และช่วงข้อมูลรายเหรียญ

gold เก็บผู้ต้องสงสัยด้วยเกณฑ์ต่ำ (5% / 5×) ส่วนหน้า Dashboard กรองด้วยเกณฑ์จริงที่ปรับได้ (ค่าเริ่มต้น 10% / 10×)

## โมเดล (bk_03)

| โมเดล | ทำนายอะไร | Baseline ที่ต้องชนะ | ตัววัด |
|---|---|---|---|
| `volume_forecast` | volume ทั้งตลาดชั่วโมงหน้า (6 ชม. ล่วงหน้า) | ค่าชั่วโมงเดียวกันเมื่อวาน | MAPE |
| `volatility_forecast` | ความผันผวนชั่วโมงหน้าของ 10 เหรียญใหญ่ | เท่าชั่วโมงก่อนหน้า | RMSE |
| `early_warning` | สัญญาณแรก (+3%, vol 3×) จะพุ่งถึง +10% ใน 1 ชม. หรือไม่ | จัดอันดับด้วย volume อย่างเดียว | AUC |
| `direction_experiment` | (ทดลอง) ราคาอีก 15 นาทีขึ้นหรือลง + จำลองเทรดหักค่าธรรมเนียม | ทายคำตอบที่เจอบ่อยสุด | accuracy |
| `anomaly_scoring` | คะแนนความผิดปกติ 0–1 ของทุกเหตุการณ์ (Isolation Forest) | — | — |

หลักการเดียวกับโปรเจกต์เดิม:
- **แบ่ง train/test ตามเวลา:** ใช้ 20% ท้ายสุดเป็นชุดทดสอบ ห้ามสุ่ม
- **Champion-challenger:** deploy เมื่อชนะทั้ง baseline และโมเดลเดิม
- **dataset ทุกรอบ** เก็บไว้ใน `ml/<model>/<run_id>/` ใน lake
- **เทรนทุก 6 ชม. แต่ออกค่าพยากรณ์ทุกชั่วโมง:** `bitkub_forecast_publish_dag` ถูกปลุกด้วย Airflow Dataset ทันทีที่ gold โหลดเข้า Postgres เสร็จ แล้วใช้โมเดลที่ deploy อยู่ทาย 6 ชม. ข้างหน้าใหม่ ค่าพยากรณ์บน Dashboard จึงมองไปข้างหน้าครบ 6 ชม. เสมอ
- **ช่วงคลาดเคลื่อน 80%:** ให้โมเดลทายต่อกัน 6 ชม. ย้อนหลังบนชุดทดสอบ แล้วใช้ควอนไทล์ 10–90 ของความคลาดเคลื่อนแยกตามชั่วโมงข้างหน้า (ความผันผวนแยกรายเหรียญ) เก็บเป็นคอลัมน์ `lower`/`upper` ในตาราง `forecasts`

**ข้อค้นพบจากการทดสอบจริง:** ทายทิศทางราคา 15 นาทีได้ถูก ~66% ดูเหมือนดี แต่ถ้าซื้อตามโมเดลแล้วหักค่าธรรมเนียม 0.5% (ซื้อ+ขาย) จะ **ขาดทุนเล็กน้อยต่อครั้ง** ความแม่นส่วนใหญ่มาจาก bid-ask bounce (ราคาเด้งระหว่างราคาเสนอซื้อ/ขาย) ซึ่งทำกำไรจริงไม่ได้ ใช้เป็นข้อสรุปในรายงานได้ว่า "ทายถูกบ่อย ≠ ทำกำไรได้"

## Dashboard (http://localhost:8002)

- **สถานะ pipeline:** จำนวนแท่งเทียนใน lake และตัวเลขของแต่ละชั้น
- **ตัวกรองที่คุมทั้งหน้า:** ช่วงเวลา, เกณฑ์ราคาพุ่ง %, เกณฑ์ volume ×, และตัวเลือกตัดเหตุการณ์ที่เกิดพร้อมกันทั้งตลาด
- **KPI:** จำนวนเหตุการณ์, % ที่ร่วงกลับจริง, ราคาพุ่งเฉลี่ย, เวลาก่อนร่วงกลับ, เหรียญที่เจอบ่อยสุด
- **รายการเหตุการณ์ + กราฟแท่งเทียน:** กดเลือกเหตุการณ์ได้ ในกราฟมีแถบช่วงพุ่ง, เส้นราคาก่อนพุ่ง, จุดสูงสุด และ volume
- **อันดับเหรียญเสี่ยง:** ติดป้ายเหรียญใหม่หรือสภาพคล่องต่ำ และมี heatmap วัน × ชั่วโมงที่เกิดบ่อย
- **พยากรณ์:** volume ตลาด และความผันผวนรายเหรียญ ล่วงหน้า 6 ชม. (อัปเดตทุกชั่วโมง) พร้อมแถบช่วงคลาดเคลื่อน 80%
- **Early warning:** สัญญาณแรกใน 48 ชม. ล่าสุด พร้อมความน่าจะเป็นและผลที่เกิดขึ้นจริง
- **ผลโมเดลเทียบ baseline** พร้อมกล่องสรุปผลการทดลองทายทิศทางราคา
- **ภาพรวมตลาด 24 ชม.:** เหรียญที่ขึ้นหรือลงแรงสุด
- **คุณภาพข้อมูล:** แท่งใหม่ต่อรอบ และสภาพคล่องรายเหรียญ
- **ตารางราคาเหรียญ:** ทุกเหรียญที่เฝ้าดู มีกราฟ 7 วัน ค้นหาได้ เรียงลำดับได้ แบ่งหน้าละ 15 รายการ
- **รายละเอียดเหรียญ:** กดที่เหรียญเพื่อดูกราฟราคา 7 วัน–1 ปี พร้อมจุดที่เคยเกิดเหตุการณ์น่าสงสัย
- **ความสัมพันธ์ระหว่างเหรียญ:** heatmap ค่า correlation ของ 15 เหรียญใหญ่ และทุกเหรียญเทียบกับ BTC
- **ทาย vs ของจริง (backtest)** และ **ความแม่นของโมเดลแต่ละรอบ**
- **ดาวน์โหลด CSV:** ตารางราคา, เหตุการณ์ตามตัวกรอง, ข้อมูลราคารายเหรียญ (`/api/export/*.csv`)
- **ปุ่ม ⓘ:** อธิบายศัพท์ทุกคำบนหน้าเว็บ
